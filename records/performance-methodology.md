# 性能优化记录与评测口径

每项优化先回答“为什么做、改了哪里”，再用基线和优化后的证据回答“确实改善了什么”。结构是总索引 README → optimizations/<id>/README.md → metrics、profiles、scripts。状态分类与证据强度分开维护；未测试不等于无收益，局部改善也不等于服务改善。

## 一项优化必须记录什么

1. 问题与动机：用户场景、base 的瓶颈、为何值得处理、可证伪的假设。
2. 优化位置：调度、CPU/GPU 空隙、算子、内存拷贝、布局、批处理或组合；精确文件、符号和提交。
3. 优化原理：原路径与新路径、数据依赖、数学等价条件、启用与回退条件、增加的开销。
4. 基线与实验条件：精确提交和源码指纹、权重、依赖、GPU、启动参数、采样、并发、请求集和校验值、预热、重复顺序、是否独占。
5. Base profile：服务阶段时间线、请求身份、动态 batch/形状、CPU 等待/同步、CUDA kernel 与 memcpy；找出关键路径，不能只列耗时最多的算子。
6. 优化后 profile：按相同请求/形状/阶段对照，记录 kernel、拷贝、GPU 活跃区间、空隙和阶段耗时的变化；同时保存原始 trace 和分析脚本。
7. 性能：每请求 cost、RTF、首包、吞吐和播放连续性；各并发点列 base、优化、变化、样本数与波动。
8. 正确性与质量：数值、graph/eager、流式状态、失败/截断、ASR、相似度、长音频与听感；缺失项写明。
9. 因果归因：设计假设、直接观测和待证实项分列；用逐项启停或形状控制判断改善来自哪里。
10. 结论：是否值得提 PR、收益范围、回退场景、未解决问题、作者归属及下一步；保留无收益与关闭记录。

## 指标定义

| 指标 | 定义与报告要求 |
| --- | --- |
| 每请求 cost（秒或毫秒） | 本记录中指每请求推理耗时。现有 serving benchmark 可观测值为客户端发送 HTTP 请求到完整音频接收结束的 elapsed/latency，包含服务端排队、预处理、推理、codec 和传输；不是货币、不是纯 GPU 时间。报告 mean/p50/p95/p99。若有服务端内部耗时，另列 stage compute/queue，不混用。 |
| 请求 RTF | 每请求 elapsed / 实际生成音频时长；先逐请求算比值，再汇总 mean/p50/p95/p99，越小越好。RTF<1 表示完成耗时小于音频时长，不保证首包或持续播放。 |
| 首包 TTFA/TTFC | 客户端发送到首个非空音频负载到达；列 mean/p50/p95/p99，注明是 PCM HTTP chunk 还是解码后的音频 chunk。不是响应头 TTFB，也不是文本 TTFT。 |
| 服务音频吞吐 | 总生成音频秒 / 测量墙钟秒，越大越好；与请求 RTF 的均值不是互为倒数。并发时不能把吞吐倒数当作单请求 cost。 |
| 请求吞吐与 token 吞吐 | 成功请求或 completion tokens / 测量墙钟秒；同时记录音频长度和 token 数，避免生成长度变化误导。 |
| 流式连续性 | chunk 间隔、最大播放欠载时长及达标率；首包变快不保证流式体验更好。 |
| 失败、截断、显存 | 请求数、成功数、失败数、终止原因、预算截断和显存峰值，全部保留。 |

闭环负载的客户端等待并发槽位不包含在单请求 send→complete 中；服务端收请求后的排队包含在内。开放环负载还需单列 planned arrival→first audio/complete，防止遗漏客户端迟发等待。网络位置必须注明：同机 loopback 不代表远程公网首包。

## Profile 与性能对照的区别

带 profiler 的 cost/RTF/首包用于定位，不直接与无 profiler 的吞吐对比；profiler 会改变 CPU/GPU 开销和批处理。另保留无 profiler 的性能对照。所有 trace 标注冷/热路径、预热范围、采样阶段、进程/stream 和时钟；跨进程合并前先验证时钟基准。GPU kernel 时长之和含并发重叠，不能当作墙钟占比；GPU 空隙也不能仅凭空白认定是调度缺陷。

机制判断分为：代码可证（替换或去掉了什么）、profile 观测（特定输入实际执行了什么）、服务关联（端到端指标如何变化）、因果确认（相同条件逐项启停且可复现）。只有达到相应层次才写对应结论。估算理论收益需说明关键路径占比和测量边界。

## 基线复用和权限

相同基线、权重、依赖、硬件、公共参数、语料、预热、采样、无竞争负载时可复用基线作初筛；小收益、长时间间隔或条件变化应刷新。叠加优化以当前已启用版本作为增量对照。慢请求不得删去以美化结果；一次顺序对照不能给出重复运行置信度。

GPU 诊断与性能测量遵守用户当次授权，不能把本次允许理解为之后随时可打断服务。临时停服须记录恢复与健康检查。公开目录不放凭据、权重或音频；大型 trace 保留位置、SHA256 与可复现命令，摘要不可伪装成完整轨迹。
